# Бот контролю обробки повернень

Telegram-бот для автоматичного контролю обробки повернень на складі. Працює у конкретній гілці (топіку) супергрупи, надсилає нагадування за розкладом і фіксує фото-підтвердження.

---

## Швидкий старт

### 1. Вимоги

- Python 3.11+
- Telegram-бот з правами адміністратора у супергрупі

### 2. Встановлення

```bash
git clone <repo-url>
cd Bot-zayobis
pip install -r requirements.txt
```

### 3. Налаштування `.env`

Скопіюйте `.env` і заповніть своїми значеннями:

```bash
cp .env .env.local   # або відредагуйте .env напряму
```

| Змінна | Опис | Приклад |
|---|---|---|
| `BOT_TOKEN` | Токен бота від @BotFather | `1234567890:AAF...` |
| `GROUP_CHAT_ID` | ID супергрупи (від'ємне число) | `-1001234567890` |
| `THREAD_ID` | ID гілки (топіку) всередині групи | `5` |
| `RESPONSIBLE_USER_IDS` | ID відповідальних через кому | `111111111,222222222` |
| `ADMIN_USER_IDS` | ID адмінів через кому | `333333333` |
| `WEEKDAY_DEADLINES` | Дедлайни пн–пт (HH:MM через кому) | `11:00,14:00,17:00,20:00` |
| `WEEKEND_DEADLINES` | Дедлайни сб–нд (HH:MM через кому) | `11:00,12:00,18:00` |
| `PRE_REMIND_MINUTES` | Перше нагадування (хв до дедлайну) | `60` |
| `FINAL_REMIND_MINUTES` | Друге нагадування + відкриття вікна фото (хв до дедлайну) | `30` |
| `WORKDAYS_ONLY` | `true` — вихідні повністю пропускаються | `false` |
| `TIMEZONE` | Таймзона за [списком](https://en.wikipedia.org/wiki/List_of_tz_database_time_zones) | `Europe/Kyiv` |

### 4. Запуск

```bash
python bot.py
```

## Як отримати потрібні ID

### GROUP_CHAT_ID

1. Додайте бота в групу.
2. Надішліть будь-яке повідомлення в групу.
3. Відкрийте у браузері:
   ```
   https://api.telegram.org/bot<BOT_TOKEN>/getUpdates
   ```
4. Знайдіть `"chat":{"id": ...}` — це і є `GROUP_CHAT_ID` (від'ємне число для супергруп).

### THREAD_ID

1. Відкрийте потрібну гілку (топік) у Telegram Web або десктоп-клієнті.
2. У URL знайдіть параметр після назви групи — це і є THREAD_ID.
   Або надішліть повідомлення у гілку та подивіться `message_thread_id` у `getUpdates`.

### USER_ID (відповідальні / адміни)

Напишіть боту @userinfobot — він поверне ваш числовий ID.

## Права бота в групі

Бот повинен бути **адміністратором** супергрупи з такими правами:
- Надсилання повідомлень
- Управління темами (топіками)

Без цих прав бот не зможе писати в гілку.

## Розклад роботи

| День | Дедлайни |
|---|---|
| Понеділок–П'ятниця | 11:00 · 14:00 · 17:00 · 20:00 |
| Субота–Неділя | 11:00 · 12:00 · 18:00 |

> Якщо `WORKDAYS_ONLY=true`, вихідні дні пропускаються повністю.

### Хронологія одного слоту (приклад: дедлайн 14:00)

| Час | Подія |
|---|---|
| 13:00 | Перше нагадування: «Обробіть повернення» |
| 13:30 | Друге нагадування: «Обробіть повернення та надайте фото» → відкривається вікно прийому фото |
| 13:30–14:00 | Відповідальний надсилає фото в гілку |
| 14:00 | Перевірка: якщо фото є → ✅, якщо ні → ❌ (сповіщення в гілку + DM) |

## Команди бота

Команди доступні **в гілці групи** або **в особистих повідомленнях** з ботом.

### `/status`

Показує статус усіх слотів за поточний день.

```
📋 Статус повернень за 2026-05-04 (будній)

✅ 11:00 — done
⏳ 14:00 — pending
⏳ 17:00 — pending
⏳ 20:00 — pending
```

### `/report YYYY-MM-DD`

Детальний звіт за будь-яку дату.

```
/report 2026-05-03
```

```
📊 Звіт за 2026-05-03

✅ 11:00 — done (підтв. 2026-05-03T10:52)
❌ 14:00 — missed
⏭️ 17:00 — skipped — вихідний
✅ 20:00 — done (підтв. 2026-05-03T19:45)
```

### `/skip HH:MM причина`

Позначити слот як пропущений (**тільки для адмінів**). Скасовує всі заплановані нагадування для цього слоту.

```
/skip 14:00 технічне обслуговування складу
```

## Логіка фото-підтвердження

1. Фото зараховується **тільки** якщо виконані всі умови:
   - Надіслано у правильну гілку (`THREAD_ID`)
   - Від користувача зі списку `RESPONSIBLE_USER_IDS`
   - У часовому вікні між другим нагадуванням і дедлайном
2. Якщо фото надіслано поза вікном — бот відповідає: «📸 Скрін отримано, але поза розкладом»
3. Фото від інших користувачів ігнорується мовчки

### База даних (`returns.db`)

Таблиця `tasks`:

| Поле | Тип | Опис |
|---|---|---|
| `id` | INTEGER | Первинний ключ |
| `date` | TEXT | Дата (YYYY-MM-DD) |
| `deadline_time` | TEXT | Час дедлайну (HH:MM) |
| `status` | TEXT | `pending` / `done` / `missed` / `skipped` |
| `photo_file_id` | TEXT | File ID фото в Telegram |
| `confirmed_by_user_id` | INTEGER | ID користувача, що підтвердив |
| `confirmed_at` | TEXT | Час підтвердження (ISO) |
| `notified_pre` | INTEGER | 1 якщо перше нагадування надіслано |
| `notified_final` | INTEGER | 1 якщо друге нагадування надіслано |
| `skip_reason` | TEXT | Причина пропуску |

## Відновлення після перезапуску

При старті бот:
1. Відновлює всі незавершені слоти поточного дня
2. Перепланує майбутні нагадування та перевірки
3. Слоти, чий дедлайн минув під час офлайну зі статусом `pending`, автоматично позначаються як `missed`

---

## Логи

Логи пишуться одночасно в консоль і файл `bot.log` з ротацією (5 МБ × 3 файли).

Рівні: `DEBUG` → файл, `INFO` → консоль.

```bash
# Переглянути останні записи
tail -f bot.log
```

## Типові проблеми

| Проблема | Причина | Рішення |
|---|---|---|
| Бот не пише в гілку | Немає прав адміна або не увімкнено топіки | Зробіть бота адміном з правом на теми |
| «Відсутні змінні середовища» | Не заповнено `.env` | Перевірте всі обов'язкові поля |
| Фото не зараховується | Надіслано поза вікном або не в той топік | Надсилайте в потрібну гілку після другого нагадування |
| DM не доходить відповідальному | Користувач не написав боту жодного разу | Відповідальний має спочатку написати `/start` боту |
